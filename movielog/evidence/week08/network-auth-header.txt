# 8주차 FE 실서버 Network 기록 — Authorization 헤더 "있었는지"만 기록 (값은 어디에도 남기지 않음)

측정 방법(하네스): Flutter Web(5173) → 기록용 프록시(3100) → NestJS 8주차 서버(3101), 그리고 TMDB 자리에 대역 서버(3200).
프록시와 대역 서버가 요청마다 method · path · status · Authorization 의 "종류"만 적었다. 종류의 뜻:
  none       = Authorization 헤더 없음
  jwt-like   = "Bearer eyJ…" 로 시작(MovieLog JWT처럼 생긴 값). 값 자체는 기록하지 않았다
  tmdb-dummy = 이 실험용으로 .env에 넣은 가짜 TMDB 토큰과 같은 값(TMDB 전용 Client가 붙이는 것. MovieLog JWT 아님)
주의: ① 브라우저가 보내는 CORS 사전 요청(OPTIONS)에는 규칙상 Authorization이 없어서 아래 표에서는 빼고 따로 개수만 적었다.
      ② 포스터 이미지(image.tmdb.org)는 브라우저가 직접 받는 요청이라 이 프록시를 거치지 않는다. 앱 코드에서 이미지는 Image.network로 받고 Dio(=AuthInterceptor)를 거치지 않는다.
      ③ 계정 B 생성·B의 로그인·B의 평점 등록은 서버(3101)에 curl로 직접 보냈다. 앱의 요청이 아니라 아래 기록에 없다.
      ④ GET /members/email/{email} 4건 중 3건은 하네스 점검용 curl(ready@test.dev, x@y.zz)이고, 앱(회원가입 화면)이 보낸 이메일 중복 확인은 1건이다.

전체 기록: 요청 114건(사전 요청 OPTIONS 44건 포함), 표시 대상 70건

## 2. 확인한 규칙

- TMDB(대역) 요청 중 "TMDB 토큰이 아닌 값"이 실린 것: 0건
- 보호 경로가 아닌 MovieLog 경로(/auth/login · /members · 중복 확인)에 JWT가 실린 것: 0건
- 보호 경로(GET·PATCH /members/me, /ratings…)인데 JWT 없이 나간 요청: 0건
- 로그인(POST /auth/login), 회원가입(POST /members), 이메일·닉네임 중복 확인(GET)은 모두 none
- 평점 등록·수정 요청 body의 key: POST /ratings = movieId, score (comment는 비어 있으면 생략) / PATCH /ratings/{id} = score, comment / PATCH /members/me = nickname. memberId는 어디에도 없다
